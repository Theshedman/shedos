<h1 style="margin-top:.7rem;">Commands</h1>

Every ShedOS tool is reachable as a subcommand of <code>shedman</code>. Long flags are the canonical spelling; short flags (<code>-y</code>, <code>-n</code>, <code>-d</code>, …) are aliases you can use wherever they're listed below.

<Callout variant="note" label="Note"><Fragment set:html={String.raw`Run <code>shedman</code> with no arguments to list every installed subcommand with a one-line summary. <code>shedman help &lt;cmd&gt;</code> and <code>shedman &lt;cmd&gt; --help</code> both show a subcommand's full usage.`} /></Callout>

## Discovery

<Fragment set:html={String.raw`<table><thead><tr><th>Command</th><th>Does</th></tr></thead><tbody>
  <tr><td><code>shedman</code></td><td>List every subcommand with one-line summaries.</td></tr>
  <tr><td><code>shedman help &lt;cmd&gt;</code></td><td>Show <code>&lt;cmd&gt;</code>'s <code>--help</code>.</td></tr>
  <tr><td><code>shedman version</code></td><td>Print the installed <code>shedos-system</code> package version.</td></tr>
</tbody></table>`} />

Shell tab-completion is installed for bash, zsh, and fish. Man pages are available too: <code>man shedman</code>, <code>man shedman-update</code>, <code>man shedman-apply</code>, etc. Third-party packages can drop their own subcommands into <code>/usr/libexec/shedman/</code>.

## Daily upgrades

<code>shedman update</code> is the primary upgrade command. It wraps <code>pacman -Syu</code>, <code>yay -Sua</code> (if installed), and <code>shedman config --sync</code> into one interactive flow bracketed by a snapper pre/post snapshot pair.

<Fragment set:html={String.raw`<table><thead><tr><th>Command</th><th>Does</th></tr></thead><tbody>
  <tr><td><code>shedman update</code></td><td>Interactive: list pending updates, prompt <code>y/N</code>, run pacman → yay → config sync.</td></tr>
  <tr><td><code>shedman update -y</code></td><td>Unattended: threads <code>--noconfirm</code> through pacman/yay. Conflicts still drop <code>.shedosnew</code>.</td></tr>
  <tr><td><code>shedman update -l</code></td><td>Print recent snapper snapshots (rollback candidates).</td></tr>
  <tr><td><code>shedman update -r &lt;N&gt;</code></td><td>Roll back to snapshot <code>N</code>. Reboot required.</td></tr>
  <tr><td><code>shedman update --history</code></td><td>Open the upgrade-history TUI.</td></tr>
</tbody></table>`} />

## Declarative state

<code>/etc/shedos/system.toml</code> is the source of truth for systemd units, drop-ins, pacman repos, snapper configs, and the Postgres service shape.

<Fragment set:html={String.raw`<table><thead><tr><th>Command</th><th>Does</th></tr></thead><tbody>
  <tr><td><code>shedman apply</code></td><td>Plan, prompt, apply.</td></tr>
  <tr><td><code>shedman apply -n</code></td><td>Plan and exit.</td></tr>
  <tr><td><code>shedman apply --validate</code></td><td>Parse and validate the TOML; exit 0 if OK, 2 on schema error.</td></tr>
  <tr><td><code>shedman doctor -d</code></td><td>Unified diff for every drift entry.</td></tr>
  <tr><td><code>shedman doctor -f</code></td><td>Delegate to <code>shedman apply --yes</code>.</td></tr>
</tbody></table>`} />

<Callout variant="warn" label="Warning"><Fragment set:html={String.raw`<code>shedman apply</code> is intentionally <strong>not</strong> timer-driven — surprise reconciles are hostile. <code>shedman doctor</code> runs on a 6-hour user timer and pings the waybar pill + mako if drift appears.`} /></Callout>
